# Matchcut

导出支持 720p、1080p、2K（2560 × 1440）与 4K（3840 × 2160）；视频、封面和项目文件的输出尺寸一致，预览保持轻量。资源对比、雷达与统计标签包含指标图标，小龙和大龙用独立图形，文字和缺失值继续保留。照片和英雄原图清晰度受来源限制，4K 不会补出原图没有的细节。

三个游戏的选手照片模式在缺图时统一显示 LPL 官网使用的人物剪影，适用于阵容、排行、主视觉和素材管理。占位 PNG 随应用内置并保留透明背景；资料库仍标记缺图，补齐真实照片后自动替换。来源见 `public/assets/placeholders/SOURCES.md`。

视频的英文标题、队名、选手名与数字使用 Orbitron；中文标题、雷达标签、数据表和字幕统一使用站酷庆科黄油体。字体随应用内置，导出前等待字体就绪。中文字体出处与许可见 `public/assets/fonts/SOURCES.md`。

本机运行的 Dota 2 / 英雄联盟 / CS 赛后视频工作台。内置真实比赛数据，打开后点击「一键生成视频」，输出适合电脑观看的 **16:9 横屏电竞视频**。默认无音轨、无配音；可导入自己的 BGM，预听、调音量并随视频导出。

画面参考 [Rock-Radar](https://github.com/TablemanLiu/Rock-Radar)：大幅六维雷达、选手名字、高清英雄图、发光轮廓与粒子。默认按一至五号位展示五组对位，每组先聚焦双方选手，再叠加比较。标准节奏约 2 分 04 秒，其中五组对位各 18 秒；只选一个位置或「双方伤害最高」模式时，该组 24 秒。其余四幕为赛果、经济走势、伤害排行和赛后定格。动画由视频帧驱动，可重复导出，不依赖录屏。

## 使用

需要 Node.js 22.13 或更新版本（使用内置 SQLite）。首次从 GitHub 克隆后，运行 `npm ci` 和 `npm run build` 安装、构建，然后运行 `npm start`，或使用下方启动脚本。

完成首次安装后，macOS 双击 `启动 Matchcut.command`，浏览器打开 <http://127.0.0.1:4317>；以后正常使用不需要打开代码编辑器。

第一次直接生成内置比赛即可。也可以输入比赛编号，或点击「浏览最近职业赛」。

- **指定比赛**：用已缓存数据重复渲染。可修改本场标题和逐段字幕。
- **自动最新**：每次生成寻找最新已解析的职业赛。可关注战队编号跨赛事跟进，也可用联赛编号限定当前届次。保留外观设置，为新比赛重新生成标题和字幕，避免上一场的文案混入新视频。
- 四套配色：黑金荣耀、烈焰对决、极地赛场、霓虹交锋。黑金使用曜黑底色、金色和银色区分双方。默认「高燃」特效增强粒子、火花拖尾、扫光、环形雷达光带和角色辉光，也可切换为「收敛」。
- 预览下方切换全部五组 / 单独位置 / 双方伤害最高，并可点击具体对位跳转预览。「核对 / 修正选手位置」可交换位置，只影响当前比赛；自动选择新比赛会重新读取位置。
- 战队颜色、栏目名称、结尾、字幕、阅读节奏、清晰度和对比偏好均可修改。
- 外观和数据筛选偏好自动保存到 `data/preferences.json`。导出/导入项目 JSON 可以恢复某场比赛的完整文案与样式。
- 网页预览与导出共用同一套 React 视频组件。

### CS Demo 与选手对比

打开 <http://127.0.0.1:4317/?game=cs2>。内置 Roobet Cup 2023 的 OG Esports 7:13 Monte（Anubis）真实数据，已收录十名选手照片、战队队标和地图徽标。

- 点击「导入 CS Demo」选择已解压的 `.dem`（最大 1 GB），使用 `@akiver/cs-demo-analyzer` 在本机解析。接受完整 5v5 CS2 / CS:GO 地图，支持常规 MR12 / MR15 和 MR3 加时；不完整、比分冲突、替补或机器人比赛会明确拒绝。重复导入按文件 SHA256 复用缓存。
- 默认比较双方对应的 K/D/A 名次：**先击杀多，再死亡少，最后助攻多**，伤害不参与排序。可显示全部五组或单独一个名次。
- 也可切换「按选手位置」：手动指定狙击手、突破手、自由人、辅助、指挥，每队每槽一人。CS 职责可以重叠，这五槽是视频对比约定；不会根据排名猜位置。未配置的对位不能导出，配置仅属于当前地图。
- CS 成片为四幕：地图战报、选手雷达、击杀排行、赛果回顾。没有回合比分曲线。雷达展示击杀、ADR、KAST、爆头率、首杀、道具伤害；缺失指标显示「—」。
- 比分是回合数。Demo 的文件时间不能视为比赛日期，未提供可靠比赛日期时留空。原始 Demo、解析快照和解析器版本保存在 `data/cache/cs/<ID>/`；视频档案记录原始数据及来源。
- CS 偏好单独保存在 `data/preferences-cs2.json`；支持项目 JSON、BGM、预览和视频导出。目前按单张地图导入，不提供自动最新或 BO 汇总。

### 英雄联盟与 BO3 / BO5

打开 <http://127.0.0.1:4317/?game=lol>，内置 2024 LCK 春季决赛 Gen.G vs T1 的真实 G1–G5。默认从第一局开始，选择局数后点「一键生成视频」。

- **单局视频**：点 G1、G2…切换该局的英雄、赛果和上 / 野 / 中 / 下 / 辅五组对位。
- **系列赛汇总**：显示已收录局的胜场比分、逐局胜者、累计资源、对位雷达和选手累计伤害榜。换边按战队名称归并。
- **完整视频**：一次总览开场 → 按局号依次播放各局资源、对位与伤害榜 → 系列赛累计分析与片尾。省略每局重复的开场、片尾和汇总开场；仅有一局时省略累计分析。装备、技能、符文仅出现在对应单局，战队颜色跟随战队跨局保持一致。章节按钮可直接跳转，文案按局编辑，BGM 在整条时间线上连续播放。三种模式分别保留标题与文案，项目导出和偏好保存精确局数清单。

完整视频验证：`npm run smoke -- --full --render` 检查章节导航、文案隔离、项目恢复、缺局、生成请求及实际章节切换渲染；可加 `--lol-match=lol-比赛ID` 指定已收录系列赛。验证不会覆盖用户偏好。
- 数据使用 [Oracle’s Elixir 下载页](https://oracleselixir.com/tools/downloads) 的年度 CSV；属于第三方数据，**自动同步尚未接通**。下载后导入一次，原始数据留在本机，之后重复生成不必再导入。更新比赛库需导入新的 CSV。
- 英雄素材完整内置：Riot Data Dragon 16.20.1 的全部 173 个英雄，头像 PNG 和默认皮肤加载立绘 JPG 共 346 张，离线可用。新英雄通过 `matchcut-data` 的 `npm run sync:lol` 更新，再导出至应用；不再只收录示例比赛出现的英雄。立绘为获取时的美术，来源见 `public/assets/lol/SOURCES.md`。
- CSV 无通用系列赛 ID：按联赛、双方战队、相邻时间和递增局号分组；局号重置或间隔超过八小时会拆开。分组是推定的，生成前可查看组内 G 编号；不推断 BO 赛制或最终冠军。比分仅表示已收录局，缺 G1 或中间局会明确标记，无法推断未导入的末尾局。
- 对位按位置累计，轮换选手的名字共同列出。伤害排行按战队内每个选手分别统计，避免把多人伤害算给一人。总经济/分、补刀/分、伤害/分为总量除以出场总分钟数；参团率为累计击杀加助攻除以对应出场局的队伍总击杀。辅助视野等计数累计，有任一局缺失则显示「—」。
- 项目 JSON 保存模式和确切的比赛 ID 集合，成片档案保留每局原始快照与来源。旧单局项目仍可导入。LoL 偏好独立保存在 `data/preferences-lol.json`。
- 「导入 BGM」支持 MP3 / M4A / WAV / AAC / OGG / FLAC，最大 100 MB，可选循环并自动首尾淡入淡出。无 BGM 时保持静音。有 BGM 时导出 AAC 音轨。不添加配音。
- 五段字幕都可以留空；清空后不显示对应字幕，但保留镜头时长。

输出位于 `output/<生成时间>-<编号>/`：

| 文件           | 用途                                                    |
| -------------- | ------------------------------------------------------- |
| `matchcut.mp4` | H.264 横屏视频，1920×1080 或 1280×720，30 fps，可选 BGM |
| `cover.png`    | 对应封面                                                |
| `captions.srt` | 按阅读节奏编排的字幕                                    |
| `publish.txt`  | 标题、数据出处和文案草稿                                |
| `project.json` | 模板和文案，可在工作台重新导入                          |
| `source.json`  | 原始数据、每局来源及获取时间，便于核对                  |
| `job.json`     | 生成状态；重启后保留历史                                |

字幕和场景文本构成静音叙事，不依赖任何文字或语音生成 API。个人设置的文案应自行核对，默认文案只描述计算得到的事实，不虚构团战过程。

## 数据来源与长期维护

数据直接来自 [OpenDota 文档](https://docs.opendota.com/)公开描述的 API，**不抓取网页 DOM，不依赖登录 Cookie，不需要 API key**。当前来源验证通过不等于第三方保证永久免费或永不变更。

- `/api/proMatches`：近期职业赛及联赛编号。列表缓存三分钟，并合并并发请求。
- `/api/matches/{id}`：完整单场数据。只有通过校验的比赛才存入本地，随后可离线重做。
- 请求串行节流，429/服务异常有限重试，超时明确反馈。一次自动查找最多检查八场已解析候选，不进行大规模轮询。
- 无完整选手字段、时间轴不一致、重复玩家、经济曲线未解析时阻止生成。不会把缺失数据当成零，也不会悄悄用示例数据冒充最新比赛。
- 解析有延迟；「最新」指近期 API 列表里可获得完整数据的最新候选，并不保证比赛刚结束即有结果。指定联赛若不在近期列表中会明确提示，可改用比赛编号。
- 联赛编号通常对应一个赛事届次。该届赛事结束后，继续追踪下一届时需要更换编号；关注战队编号可以跨赛事跟进，选择全部职业赛则不需维护这个筛选。
- 本地样例：Aurora Gaming vs 1win，BLAST SLAM VIII，比赛 `9035078952`。来源为 <https://www.opendota.com/matches/9035078952>，保留了完整快照。
- 战队及选手名称来自数据提供方；最新名称可能与比赛当时不同。英雄图片是可选装饰，下载失败时使用占位图，不影响数据生成。
- 十名选手所用英雄的高清渲染图来自 Steam CDN；首次加载后缓存。高清图不可用时保留普通英雄头像，同一进程内失败后一天内不重复请求。默认比赛十张高清图和字体随项目安装，可离线生成。

如果将来接口变化，修改 `server/source.ts` 和 `src/domain.ts` 的适配/校验即可，视频模板与 UI 不需要跟着改。`tests/domain.test.ts` 使用真实快照验证关键数据口径。

## 统计口径

Dota 单局在选手特写与正面对比中展示最终六格主装备，并独立展示中立物品和新版附魔。数据来自 OpenDota 的 `item_0`–`item_5`、`item_neutral` 与 `item_neutral2`，保留空格顺序；背包保留在比赛数据中但不显示，不将购买记录或使用次数视为终局装备。装备目录与示例图标由 `matchcut-data` 维护，其他比赛仅下载实际显示的图标并缓存；缺图或目录未知时保留装备 ID，主栏数据不完整时不显示装备行。

LoL 单局点击「获取装备与符文」，从 LoL Esports 公开赛程与 `feed.lolesports.com/livestats/v1` 接口补充 CSV 缺少的装备信息。必须唯一核对比赛时间、补丁、十名选手的阵营、位置、名称、英雄和终局 KDA，并确认装备与 `finished` 状态来自同一帧后才保存。记录、对应补丁的 Data Dragon 中文装备目录与图片都缓存在本机；加载已保存的比赛不额外联网。内置 2024 LCK 春决第一局的已核实快照与 14.6.1 装备图，可离线查看。

部分比赛暂停恢复后，官方接口会同时清空 KDA 计数和已有装备。累计 KDA 能核对成功，也不能证明出装完整：这类断档记录不再接入，旧版通过计数恢复保存的装备缓存也不会展示。接口仅返回暂停记录时，在编辑界面说明原因；视频中不添加提示，也不拼接或推测丢失的装备。比赛本身及系列赛 KDA 不作修改。

LoL 官方接口返回装备列表，包含饰品、消耗品及重复数量，**未提供六格位置，也不保证每名选手完整六件**。视频直接展示装备图标，保持来源顺序，重复 ID 合并标注数量，不补空栏、不推测缺少的装备。无记录时不显示装备行；接口不覆盖的比赛、无法核对或接口变化时会提示错误，保留已有数据。系列赛汇总不显示单一出装，KDA 口径不变；CS 不增加装备、武器或手雷统计。

装备验证：`npm run smoke -- --items --render` 检查预览与实际导出；加 `--live-items` 可重新核对内置 LoL 单局的官方记录，`--lol-match=lol-比赛ID` 可指定另一场已导入的单局。

选手详情和正面对比展示同一套完整统计，位置只决定雷达轴与大字号重点指标。LoL 新增伤害占比、承伤占比和经济占比，分别以同队五人对应总量为分母；承伤由 Oracle’s Elixir 的 `damagetakenperminute × 时长` 还原，经济用 `totalgold`，不混用赚取经济占比。任何队友缺少承伤时，全队承伤占比显示 `—`。系列赛先累加总量再计算，轮换选手只使用自己出场局的队伍分母。

正面对比用英雄图标标识本局角色；照片模式在选手照旁显示小英雄图标，单局不再写英文英雄名。伤害、承伤、经济、占比、视野等可比较指标在数字下方显示双方横向柱条：百分比固定使用 0–100% 尺度，绝对值在同一指标内共用尺度。K/D/A 组合值或任一方缺失时不画柱条。

「获取装备与符文」一次核对两项，分别保存成功的数据；一项失败不阻止另一项，也不清空已保存记录。官方开局符文按阵营、位置、十名选手、英雄、时间和补丁唯一核对；独立于终局装备，即使后续暂停重置也不需要用残缺装备帧恢复符文。完整展示接口实际给出的主副系、符文及属性碎片；某些记录只有八项，不补造第九项。公开赛事接口未提供召唤师技能，支持手动选两种峡谷技能、清空和自动保存，不推测实际选择。技能按本局选手与英雄绑定；单局技能、符文和装备不带入系列赛累计。

14.6 和 16.18 技能符文目录及图标随应用内置，其他补丁在主动获取符文时按对应版本缓存；图片不可用时保留已验证的 ID。加载比赛不额外联网。来源见 `public/assets/lol/loadouts/SOURCES.md`。`npm run smoke -- --items --loadouts --render` 覆盖图标、完整统计、手动技能入口、预览与实际导出，不改用户偏好。

1. 赛果来自 `radiant_win`，不根据击杀数判胜。
2. 单局模式的比分是英雄击杀数；英雄联盟系列赛开场比分是已收录局的胜场数。系列赛累计英雄击杀另行标注。
3. 经济差为天辉减夜魇，时间轴使用 API 的秒级采样时间。最大领先/落后来自采样极值，不能还原每次团战。
4. 对位使用 OpenDota 的 `position_est`，不是 `player_slot`。该字段由分路、10–12 分钟经济/补刀及早期眼位购买等估计，见 [estimatePositions](https://github.com/odota/core/blob/master/svc/util/compute.ts)。它不是官方阵容声明，工作台标明「估计」；可以手动修正，并在项目档案记录来源。成片仅展示对位与比赛数据，不显示比赛 ID、来源网址或指标公式。缺失或同队重复的位置不自动补齐，对位不完整时阻止对应模式导出。
5. 一号至三号位比较击杀、助攻、GPM、XPM、每分钟英雄伤害、建筑伤害。四、五号位比较助攻、参战率、观察守卫放置数、岗哨守卫放置数、累计眩晕秒数、英雄治疗量。参战率 =（击杀 + 助攻）/ 本方英雄击杀。缺失辅助字段显示「—」，不会补零；该轴不参与多边形绘制。
6. 每个轴按当前对比二人的较高值归一化，不能跨对位按面积排实力。默认只作本场同位置比较，不是综合能力评分或职业选手百分位。「双方伤害最高」是独立可选模式，不要求两人同位置。
7. 每分钟英雄伤害 = 英雄总伤害 / 本场总分钟数。伤害排行只看英雄伤害，不含建筑伤害。
8. 源数据会随成片保存，项目档案包含实际对位名单和位置来源。生成日期与比赛日期分别保留。

## 开发与个性化

### 共享资料库

应用代码在 [Cass-ette/matchcut](https://github.com/Cass-ette/matchcut)，战队队标、选手照片、地图图标与出处在独立的 [Cass-ette/matchcut-data](https://github.com/Cass-ette/matchcut-data) 维护。应用内保留一份可离线运行的资料快照；个人上传、绑定和偏好不上传到 GitHub，且始终优先于内置默认素材。

两个仓库放在同一级目录时，在 `matchcut-data` 中运行 `npm run validate`，再运行 `npm run export -- ../matchcut` 更新默认快照。重启 Matchcut 后载入新目录，资料版本记录在 `data/fixtures/media-catalog-version.json`。资料仓库也可构建带 SHA256 的版本包；应用暂未实现后台自动下载。CS 前 50 和 LoL 各赛区的完整资料仍待后续收录。

素材管理：<http://127.0.0.1:4317/admin>。战队图标、英雄头像和立绘分别上传，可恢复默认；支持静态 PNG、JPG、WebP，单张不超过 12 MB。战队的其他名称每行一个，匹配时不区分大小写、空格和常见分隔符。英雄按游戏与角色 ID 匹配，系列赛换边、不同英雄的历史头像均保留正确对应。

三个游戏都有独立的「选手定妆照」素材类别。Dota / LoL 在外观设置的「选手画面」中选择英雄或定妆照，CS 固定用选手照片；选项随偏好和项目 JSON 保存。选手照覆盖开场阵容、雷达、排行榜和结尾；英雄数据仍保留。照片按提供方选手 ID 绑定，缺图显示 LPL 官网人物剪影，同名不同 ID 不混用。LoL 系列赛同一位置有多人轮换时，汇总卡片不套用其中一人的照片。

可上传选手头像与定妆照，也可在选手卡片粘贴 HLTV / ProSettings 资料页链接，获取预览后点「用于该选手」。选定图片下载到本地，来源可追溯；HLTV 返回 403 时会明确提示，可换来源或上传。当前有 **164 份 LoL 选手档案、163 张真实照片**和 CS 示例十人照片，来源为 Riot / LPL 官网及 ProSettings。LoL 档案覆盖 2026 德杯 DCGI 的 60 名已出场选手、S 赛 19 队的 95 名赛前最近出场选手及另外 9 名核实过的本赛季选手。GAM 的 tiphat 官方来源只有占位剪影，保留缺图状态。最终赛事报名和完整替补名单尚未核实。

选手档案独立于战队，按稳定个人 ID 关联照片；转会不创建新档案。`data/fixtures/lol/players.json` 保存别名和来源 ID，`events.json` 单独引用个人 ID 和有日期的出场证据。尚未导入其比赛的已收录选手也能在素材库搜索。照片队服不代表历史比赛当时所属战队；图片与来源清单见 `public/assets/players/SOURCES.md`，地图徽标来源见 `public/assets/cs/SOURCES.md`。

待确认的队标在素材卡片右上角显示小红点，区分「同名待确认」与「缺少队标」。用「待确认队标」筛选即可集中处理，选择或上传后红点消失；工作台也会提示本场待确认队标数量。

开场使用战队图标，缺图时显示队名缩写。预览与新导出都使用当前素材库；已生成的视频不改变。自定义素材配置保存于 `data/matchcut.sqlite`，上传文件保存于 `public/assets/library/`。恢复默认不会删除旧图片，历史任务仍能引用原文件。内置 17 支战队的图标，来源记录于 `public/assets/teams/SOURCES.md`。

同一游戏里，队名忽略大小写后与开源目录名称相同，会默认匹配图标；同名存在不同图片时保留人工选择。手动上传或绑定优先于默认，恢复默认后可回到自动匹配。用于视频的图片会先下载到本地。

队名匹配不上时，在战队右侧点击「从图标库选择」，按队名、简称或英文名搜索 [esport-team-logos](https://github.com/lootmarket/esport-team-logos)，预览后点击「绑定到当前战队」。无需修改比赛队名。绑定会下载图片并保存来源，以后同队比赛自动复用；也可以搜索其他游戏分类的队标。目录内置本地快照，点击「更新目录」获取最新名单；更新失败仍可搜索旧目录。未下载的图片首次预览或绑定需要网络，已绑定素材不依赖在线图片地址。

### 本地数据与素材加载

SQLite 保存比赛摘要、选手身份、逐场出场记录、素材查询索引和用户的图片/别名绑定。选手按稳定 ID 独立保存，战队归属来自有日期的出场记录，转会不会创建另一个选手。比赛原始 JSON 和 Demo 保留用于核对与渲染；共享的 `matchcut-data` 仍发布 JSON 与图片。

升级后首次启动会补建旧比赛索引，并将 `data/media-library.json` 的自定义配置一次性迁入 SQLite。迁移成功后旧 JSON 原样保留为升级前的备份，不再读取或更新。无效的旧配置会明确报错，不会被空数据覆盖。后续启动复用索引；LoL 导入时只更新新增或变动比赛，打开素材页不再读取全部原始比赛。

素材页按游戏、类型、名称/别名和缺图等状态在服务端查询，每页最多 60 项。搜索覆盖全部记录，切换条件回到第一页。列表使用按需生成的 WebP 缩略图（最长边 320 px，保留透明度），编辑预览与视频使用原图。缩略图缓存位于 `data/cache/thumbnails/`，可删除后自动重建。

备份或迁移个人数据时，先停止应用，再保留 `data/matchcut.sqlite` 及存在的同名 `-wal` / `-shm` 文件、`public/assets/library/`、`data/preferences*.json`、`data/cache/`、`public/assets/bgm/` 和需要的 `output/`。SQLite 包含升级后的个人修改，不能当作普通缓存直接删除。数据库、缓存和个人上传均不提交 GitHub；更新共享素材快照不会覆盖它们。

```sh
npm ci
npm run build
npm start
```

开发时运行 `npm run dev` 使用 Vite 热更新（先停止占用同一端口的服务）。修改代码后，运行 `npm run build` 并重启本地服务。修改默认文案后可运行 `npm run fixtures` 同步 Remotion Studio 的示例。

```sh
npm test
npm run smoke
npm run smoke -- --lol
npm run smoke -- --series --render
npm run smoke -- --media --render
npm run smoke -- --cs --render
```

`smoke` 在运行中的工作台执行浏览器检查，截图保存在 `output/verification/`。

代码入口：

- `src/video/MatchFilm.tsx`：分幕排版、对位轮播、动画、图表及四套色彩主题。
- `src/domain.ts`：数据口径、默认文案、阅读时长、字幕。
- `src/main.tsx` / `src/style.css`：工作台界面。
- `server/source.ts`：数据适配、缓存、限流、最新比赛选择。
- `server/cs-source.ts` / `src/cs.ts`：Demo 导入、缓存和 CS 数据校验。
- `server/player-photos.ts`：选手资料页与照片获取。
- `server/render.ts`：本地渲染、封面与档案导出。
- `data/preferences.json`：本机保存的偏好。

旧版项目 JSON 可继续导入，重新生成时使用当前横屏版式；旧版未指定对位模式的项目按原来的「双方伤害最高」恢复。内部主题键 `paper` 对应「霓虹交锋」。旧版竖屏视频原文件保留，生成历史会标明「旧版竖屏」。新项目档案记录宽高、16:9 比例、对位与模板设置。

渲染使用 Chromium。程序优先使用本机已安装的 Playwright Headless Chromium，也可用 `MATCHCUT_BROWSER=/absolute/path/to/chrome` 指定；没有可用浏览器时由 Remotion 下载。默认本地地址为 `127.0.0.1:4317`，不向局域网开放。若使用 `PORT` 更换端口，双击启动脚本中的地址也应同步修改。
